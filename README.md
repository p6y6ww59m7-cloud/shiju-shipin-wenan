# 拾句视频文案

把视频素材、口播转写、文案对比、精选组稿与归档放在同一个本地工作台。

本仓库是「拾句 · 视频与文案工作台」的完整公开源码，包含实际界面、后端、视频引擎、macOS 桌面程序源码、安装脚本与自动测试。私人文案、选题档案、登录信息及旧仓库的私人提交历史均不包含在内。

## 功能与操作顺序

1. **获取视频**：粘贴抖音、YouTube、B站、快手、X / Twitter 的分享链接，自动加入下载队列；支持每批最多 30 条。
2. **保存原画**：按下载引擎的格式策略优先选择最高可用 MP4 视频与原始音轨，支持可获取的 4K 资源；合并时不重新压缩。重复作品会先验证并复用本地文件。
3. **提取口播**：逐条勾选「转文字」后，使用本地 Whisper large-v3 FP16 与 Silero VAD 生成 TXT、SRT 和 JSON。默认不自动转写。
4. **核对与修订**：按转写时间点回看视频，编辑文字；原始转写和旧版本单独保留。
5. **对比与评分**：把文案加入选题，每组最多 8 篇，通过本机 Codex 进行短视频口播分析。当前代码默认使用 `gpt-6-astra`、`high` 推理强度，需要账号具有对应模型权限。
6. **精选与组稿**：挑选整篇、段落或句子，调整顺序并组合文稿，再手动确认最终稿。支持历史档案、删除恢复与旧版精选找回。
7. **按需同步飞书**：连接自己的飞书账号后，同步原文、来源、评分、精选与最终稿；未连接时仍可在本机编辑和保存。

平台登录、地区、网络和作品权限会影响视频可用性。下载或转写失败会显示原因，不会把不完整文件当作成功结果。

## 运行环境

- 完整桌面与视频功能面向 **macOS 13 或更新版本、Apple Silicon**。
- Node.js 22 或更新版本；本项目只使用 Node.js 内置模块，无需安装 npm 依赖。
- Python 3、Xcode Command Line Tools（用于编译 Swift 原生辅助程序）。
- Google Chrome（用于需要登录或验证的视频平台）。
- 文案评分需要本机 Codex CLI 及用户自己的登录；飞书同步需要 `lark-cli` 及用户自己的授权。
- 转写模型约 3.1 GB；首次安装需要下载运行资源，并预留视频素材空间。

## 从源码启动

```bash
git clone https://github.com/p6y6ww59m7-cloud/shiju-shipin-wenan.git
cd shiju-shipin-wenan
npm test

# 首次安装视频下载与转写资源
npm run setup:video
npm run verify:video

# 启动本地工作台
npm start
```

打开 <http://127.0.0.1:43828/>。首次启动会生成新的本地工作数据和内置演示选题，不需要任何私人数据文件。

只查看文案界面、暂不安装视频资源时，可运行：

```bash
SHIJU_VIDEO_DISABLED=1 npm start
```

安装 macOS 桌面入口和登录后启动服务：

```bash
npm run install:mac
```

安装脚本根据当前用户和源码位置自动生成 LaunchAgent 配置。安装前退出桌面窗口，并完成正在进行的任务。`deployment/macos/` 中保留的是路径占位示例，通常无需手工编辑。

可通过 `CODEX_CLI`、`LARK_CLI` 指定命令路径，通过 `PORT` 修改端口，通过 `SHIJU_DATA_DIR` 指定工作数据目录。

## 源码结构

| 路径 | 内容 |
| --- | --- |
| `dist/` | 实际运行的 HTML、JavaScript、样式和图标 |
| `server.mjs`、`lib/` | 本地服务、评分、文案选择、组稿、归档与飞书同步 |
| `video-engine/` | 视频解析、下载、独立浏览器会话、队列、本地转写与完整性校验 |
| `native/` | macOS 桌面入口的 Swift 源码与构建脚本 |
| `scripts/` | 安装、流程验收和评分耗时测试脚本 |
| `test/`、`video-engine/test/` | 自动测试，使用临时目录和测试数据 |
| `video-engine/runtime-manifest.json` | 第三方运行资源版本、下载地址及 SHA256 |
| `video-engine/native/vendor/*-LICENSE` | 第三方组件许可证 |

模型和第三方可执行文件由安装脚本从清单中的地址获取，未作为大文件提交。相关下载器、转写服务、原生程序的集成与构建源码均在仓库内。

## 私人数据与版本保存

运行时产生的 `data/`、视频和音频、转写结果、浏览器资料、Cookie、会话令牌、飞书表格配置、日志及本地备份都已加入忽略规则。请用自己的账号登录和授权，不要把这些文件强制加入 Git。

工作台默认使用项目下的 `data/`；视频服务的数据默认位于 `~/Library/Application Support/抖音视频导出助手/`，下载的视频默认位于 `~/Downloads/抖音视频导出/`。这些目录属于本地私人数据，需要自行另行备份。

公开仓库从干净的首次提交开始，保留源码版本；发行标签可用于取回对应版本。更新源码后运行 `npm test`，确认没有加入私人文件，再提交和推送。

## 验证

```bash
npm test
npm run verify:video
```

`npm run verify:flow` 是可选的真实流程验收，会下载公开样例并调用本机 Codex。附加 `-- --feishu` 后还会向当前账号的飞书写入测试记录；仅在准备好相应账号与环境时手动运行。
